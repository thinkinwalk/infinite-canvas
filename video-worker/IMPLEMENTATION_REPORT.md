# Replicate 视频与数字人接入结果

## 完成范围

导航保持「图片制作 → 视频制作 ▼ → 数字人 → 无限画布」。视频创作入口为 /video/cloud-create，各工具进入独立工作台。

前端 → 本站 Go 接口 → 读取后台已保存的 Replicate Token → 云模型 → 本站保存结果 → CPU worker 字幕/剪辑 → 素材/画布。

- 已写入八项模型适配：Qwen3-TTS、Wan2.2 S2V、Sync LipSync2、Wan2.2 Animate Replace、Topaz、Wan2.2 I2V Fast、Wan2.7 VideoEdit、VACE14B。
- 登录用户可报价、确认算力点、创建、查询、取消和下载自己的任务；素材上传登记所属用户。Replicate Token 不返回浏览器。
- 创建、平台扣费及流水为一个事务，平台任务 ID 为幂等键；供应商明确失败时只返还一次平台算力点。供应商自身费用仍以账单为准。
- 网络或 5xx 等导致提交未确认时不重发收费请求；管理员可在任务记录填写已核对的 prediction ID，后台比对模型、版本和输入后关联原任务。
- 后台各功能可配置算力点/次；留空或 null 时仅管理员测试，显式 0 表示普通用户免费使用平台算力点。供应商费用并不因此免费。
- CPU worker 增加本站登录网关及任务、结果文件归属校验；生产默认 /api/v1/video-worker，内部服务令牌只放服务器。
- 视频、阶段结果、封面和素材继续保存在本浏览器。后端保存云任务与云输出，并不等同于素材库已支持跨浏览器同步。

## 服务器部署草案

现有服务器已只读检查为 4 vCPU、约 7.8 GiB RAM、无 NVIDIA GPU。方案将模型推理交给 Replicate，服务器运行 Go 网站与 FFmpeg/Whisper CPU 服务，正式使用不依赖开发电脑。

配置草案：server-customizations/docker-compose.video.example.yml。部署需先核对现有 Compose 网站服务名、网络和构建路径，并替换为包含本次 Go/前端改动的新镜像；该覆盖文件不会自动更新旧镜像代码。

准备顺序：

1. 备份现有数据库、Compose、网站持久化数据，记录当前镜像以便回退；先在独立环境运行新版后端，验收同一任务重复提交、失败返还、不同用户互访拒绝、断连恢复、价格 null 和管理员关联。
2. 确定 CPU 并发/排队及数据保留策略后实现队列，再确认实际服务器资源占用；建议首发同时执行 1 个 CPU 处理任务、其余排队，处理失败返回错误并由用户手动重试；此值尚未获审批和实施。
3. 建立内部 video-worker 容器，挂载 /opt/infinite-canvas/video-worker-data 和 video-worker-models；Whisper small 权重预置到 whisper-small 子目录。不映射 worker 公网端口。
4. 网站设置 VIDEO_WORKER_URL、两容器共用的 VIDEO_WORKER_TOKEN 和 PUBLIC_BASE_URL=https://studio.lingzhouai.com。Replicate 继续读原后台私有配置。
5. 管理员设置每项平台价格，先限定管理员验收；逐步开放给普通用户。确认 HTTPS 素材地址可被供应商读取，云结果持久化目录位于现有 /app/data 挂载下。
6. 正式部署审批后发布，验证生产 /api/health 和真实短样片链路。若出现故障，恢复原镜像/Compose；不盲目重发未确认的收费任务。
