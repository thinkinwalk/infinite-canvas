# 数字人工作台优化方案

## 范围与结论

本轮通过比特指纹浏览器本地 CDP `63037` 检查了：

- 本地：`http://127.0.0.1:3000/digital-human`
- 对标：`https://6688ai.quantv.com/digital-human`

检查使用了独立临时标签页；用户原有标签页和窗口保留。方案已在本轮落地到数字人专用工作台；没有创建真实云任务、没有产生扣点。

结论是：本站已经具备完整的「文案 → 口播 → 数字人视频 → 剪气口 → 标题标签 → 字幕配乐 → 封面」能力和真实的照片/视频两条生成路由。现已新增数字人专用工作台，把照片说话与视频对口型拆成首屏可理解的两条路径，并把素材、任务进度和成片后期按阶段固定在可见区域；真实模型效果与扣点仍需人工验收。

## 实施状态

`/digital-human` 已采用创作、后期、结果三区布局，宽桌面创作与后期各自滚动；01–06 导航和生成/继续操作常驻。窄桌面降为编辑区加结果区，手机连续滚动，底部提供生成、继续、停止等待及查看结果，并留出安全区。高级路由、模型与处理服务检查折叠。

费用预估与正式生成共用 `digital-human-request.ts` 输入构造和真实报价接口；预估不创建任务，正式提交仍需再次确认。输入、模式、路由或账户变化清除旧报价，迟到响应被丢弃；切换账户重新上传素材引用，已打开页面可刷新模型目录。

任务保存人物/口播、文案、声音、后期参数、已有阶段文件、输入版本和已确认报价；云路线快照不依赖通用视频模型配置。恢复查询使用原任务，历史输入恢复需确认替换草稿。任务未完成时阻止重复提交；停止等待或后期查询中断保留可恢复任务；迟到结果进入历史，不覆盖新版本草稿。

结果支持初稿、剪气口版本、最终成片切换，下载、保存素材和加入画布使用所选版本。历史音频与图片按实际类型预览，封面可独立下载。上游修改保留手写标题/标签，修改标题只使封面失效，AI 替换已有正文/标题需确认；模式切换保留口播并清理不匹配人物与下游视频。字幕可增删行、编辑时间与文字、设置字色/高亮色/关键词，并在合成前检查空文字及无效时间。

CDP 隔离验收覆盖 1920×953、1440×900、1366×768、1024×768、390×844、320×740，确认无页面横向溢出、阶段定位和主操作可用，后期栏只允许表格自身横向滚动；另检查浅色手机结果预览。14 项模拟检查验证报价/取消、账户引用隔离、当前页模型刷新、迟到结果保护、快照与刷新恢复、版本预览、完整自动后期及查询中断恢复，未出现未捕获页面错误；证据位于仓库旁 `artifacts/digital-human-review/final-verification.json` 和 `final-*.png`。没有创建真实收费任务，模拟素材只用于界面验收。

类型检查仍有 4 项既有错误，位于 `video-tool/index.tsx`、`upscale-workspace.tsx` 和 `viral-recreate-workspace.tsx`，数字人相关文件未新增类型错误。真实口型/音质、实际处理输出、扣点退款、手机触摸与键盘弹起仍需业务验收；音色试听、波形、真实样片、云端归档及一致构建下的性能评估后续单独推进。

## 实页证据

### 首次核对时的本站页面（以下问题已由专用工作台调整）

在 1920×953、1440×900、1366×768 三个桌面尺寸中，页面文档高度等于视口高度，但主内容祖先容器是 `overflow-hidden`。实际数字人业务内容的 `scrollHeight` 约为 2362，而可视高度只有 897、844、712；底部的「合成字幕与配乐」「生成封面」「按当前设置自动完成后续步骤」均位于首屏下方，桌面滚轮无法把外层页面滚到这些位置。390×844 手机尺寸虽然出现内部可滚动的 `main`，但仍是长单列加嵌套滚动，生成按钮位于很深的位置。

本地首屏还同时显示高级处理方式、云模型状态、文案主题、口播文案和右侧模型/预览空态。未登录时 Qwen3-TTS、Wan S2V 和 Sync Lipsync 显示「暂不可用」，但页面仍把完整后续步骤全部展开，用户需要先理解路由、模型、素材角色和费用条件。

首次核对时的关键事实：

- `/digital-human` 复用通用 `VideoWorkbench`，数字人模式有「照片说话 · 上传照片 + 口播音频」和「视频对口型 · 上传人物视频 + 新音频」两项。
- 照片路线真实调用 `digital-human` / Wan S2V；视频路线真实调用 `lipsync` / Sync Lipsync；两者都先生成或导入口播音频。
- 字幕、剪气口、配乐、封面是独立处理步骤，输出分别保存在 `speech`、`video`、`edited`、`final`、`cover`。
- 自动流程目前在入口处无条件调用 `getWorkerCapabilities`，即使选择 Replicate 云路由也会先检查本地处理服务；这会让云端数字人因本地 worker 未连接而无法开始自动流程。
- 通用 `VideoRecord` 对数字人只保存阶段结果和部分草稿补丁，没有独立的数字人输入快照（照片/人物视频、声音模式、音色、语言、模型、规格和报价上下文）。

### 对标页面

原有已登录标签在 1920×953 显示四栏工作台：左侧 `01 IP深度学习`、中间 `02 音视频生成` 与 `03 视频编辑`、右侧 `04 标题标签关键词`、`05 字幕和音乐`，最右侧是自动化控制台和封面区。页面中心编辑栏有独立滚动容器（`scrollHeight 543 / clientHeight 477`），顶部导航和关键操作仍可见。

可借鉴的交互点：

- 首屏直接说明预计生成时间，并把余额、积分商城、会员入口放在顶部。
- 文案区把视频类型、文案类型、人物/行业、产品、卖点价格、其他要求拆成字段，另有可编辑口播正文、语言和目标字数。
- 音视频区把系统音色、自定义音色、资产库音色、音量、语速、语言、音频历史、形象选择、生成视频和导入已有数字人视频放在同一阶段。
- 每个主要动作都显示页面自己的积分价格；自动化控制台显示「开启一键自动模式」、停止任务和清除数据；封面在标题未完成时明确禁用。
- 标题、标签、关键词、字幕样式、高亮词、背景音乐和最终预览分开呈现，结果区有清晰的空态。

对标页显示的积分、时长和预计生成时间只属于对标站实页展示，尚未核对其实际扣费与上游任务，不能复制到本站。

## 原方案推荐的信息架构

保留本站顶栏、主题 token、中文文案、Zustand/localforage 和现有请求服务。新增数字人专用页面入口，复用 `useVideoWorkbench("digital-human")` 的执行逻辑，但不继续把所有卡片堆在通用 `main` 中。

### 桌面布局

- 左栏约 420–480px：模式选择、文案与口播、人物素材、生成前确认；左栏独立滚动。
- 中栏弹性宽度：当前阶段编辑器和数字人初稿预览；视频播放器、音频播放器和字幕时间轴保持可见。
- 右栏约 320–380px：阶段状态、报价、历史任务和当前最终成片；顶部固定，结果可切换初稿/后期/封面。
- 底部操作条固定在业务栏内，显示「保存草稿」「生成/继续」「停止等待」「取消已提交任务」等真实可用动作。

### 手机布局

单列连续滚动，模式和素材先出现，后期卡片按完成状态展开；底部主操作使用 `position: sticky` 并留出安全区，不遮住最后一个输入框和键盘。结果播放器、历史记录和费用说明改为可展开抽屉，避免首屏出现三列压缩内容。

## 建议的用户流程

1. **选择制作方式**
   - 「照片说话」：人物照片 + 口播音频 → 新的数字人视频。
   - 「视频对口型」：正面人物视频 + 新口播音频 → 保留原视频画面、替换口型的结果；页面明确受 Sync Lipsync 能力限制。
   - 每张卡显示当前可用模型、输入要求、预计输出范围和不可用原因；不把对标站价格作为默认值。

2. **填写文案与口播**
   - 主题/产品资料和「只朗读正文」分开，保留 AI 撰写后的可编辑草稿。
   - 语言、音色、语速、声音模式（系统音色 / 声音样本克隆）放在口播阶段；导入音频后立即显示时长和播放器。
   - 文案修改使旧音频、数字人视频和后续成片标记为待更新，不覆盖用户手写内容。

3. **准备人物输入**
   - 照片模式只接受人物图片；视频模式只接受人物视频，显示缩略图、尺寸、时长和可用格式。
   - 切换模式时阻止把图片当视频或把视频当照片发送；提示「切换模式将需要重新报价」，不静默复用旧结果。
   - 如导入已有口播视频继续后期，单独标注「跳过数字人生成」，避免与当前人物素材混淆。

4. **生成前确认**
   - 根据当前模式、人物素材、音频时长、模型和路由调用真实报价；显示计费单位、预计扣点来源、输入摘要和输出规格。
   - 未登录、模型不可用、素材无法公开访问或 worker 缺能力时，直接解释阻断原因；确认按钮禁用且不创建任务。
   - 正式提交时再次核对模式、模型、素材版本和报价，避免异步旧报价覆盖新输入。

5. **后期处理**
   - 剪气口：明确需要已生成视频和转写/时间轴；处理完成后字幕时间轴失效并要求重新识别。
   - 标题标签：标题、标签和封面依赖关系清晰；标题未完成时封面按钮显示具体条件。
   - 字幕配乐：先识别或手动编辑字幕，再选择样式/高亮词/音乐并合成；每一步都有独立结果和重跑范围。

6. **结果与历史**
   - 初稿、剪气口版本、最终成片、封面分开显示，提供播放、下载、保存素材和加入画布。
   - 任务历史展示模式、人物素材摘要、口播时长、模型/规格、费用状态、任务状态和失败原因；恢复任务只查询原上游任务，不重复提交。
   - 当前草稿与历史快照分离，查看历史不能覆盖正在编辑的内容。

## 请求和状态设计

建议新增数字人专用输入快照，例如 `digitalHumanInput`，至少包含：

- `digitalHumanMode`、`route`、人物素材引用、口播素材引用、声音模式、语言、音色/声音样本原文；
- 生成时的模型标识、分辨率/时长规格、能力快照和报价/确认上下文；
- 文案、标题标签、剪气口、字幕与配乐设置，以及每个阶段的输入版本。

沿用现有 `VideoRecord`、`draftPatch`、`replicateTask`、`workerJob` 和 `AbortController`。补充真实语义：

- 「停止等待」只停止本地轮询；已提交的 Replicate/worker 任务显示可恢复查询。
- 「取消处理任务」仅在当前渠道支持取消时显示，并区分取消请求已提交和已确认取消。
- 改变人物模式、人物素材、音频或模型后，旧报价失效；失败/迟到结果不得覆盖新版本草稿。
- 云端路由不应为生成阶段强制依赖本地 worker；只有剪气口、转写、字幕配乐、抽帧封面等实际需要本地能力的阶段才检查 worker。

## 实施顺序与文件范围

### 第一阶段：P0 可达性和模式分流

1. 新建 `web/src/pages/video-tool/digital-human-workspace.tsx`，入口只对 `digital-human` 分派专用页。
2. 复用内容替换、探店和爆款复刻工作台的独立滚动、固定操作和主题实现。
3. 将照片/视频模式、文案/音频、人物素材和主生成按钮前置；桌面与手机都能到达所有阶段。
4. 自动流程按 `route` 与实际后期步骤计算能力依赖，修复 Replicate 路由被 worker 阻断的问题。

### 第二阶段：P1 真实输入、报价和任务恢复

1. 在 `types/video-workbench.ts` 增加数字人输入/提交快照和阶段版本字段。
2. 在 `use-video-workbench.ts` 增加数字人报价前置、模式/素材校验和结果版本保护。
3. 增加初稿、剪气口、最终成片和历史任务的清晰状态与恢复入口。
4. 让模型能力卡、费用确认和不可用原因与当前后台目录保持同步。

### 第三阶段：P2 体验增强

1. 音色试听已进入待测试；继续推进音频历史、字幕样式预览和操作说明。
2. 真实本站数字人样片与同输入前后对照，避免拿对标站视频冒充本站效果。
3. 评估跨浏览器作品归档和无人值守任务，不在本阶段偷偷改变文件保留、并发、超时或重试边界。

## 口播生产第一阶段：已实现，待验收

- 入口按使用场景拆分：“照片说话”“视频对口型”位于视频制作工具菜单，直接准备人物与音频，配音文字为可选步骤。两个工具与数字人各自保存草稿和任务，复用生成、报价和恢复代码。
- 数字人工作台从文案开始，人物方式选择移到第二步；人物上传同时接受照片和视频，并自动匹配照片说话/视频对口型。已有音频仍可跳过文案，完整口播的后期流程保留。

- 三种写稿入口：结构化资料生成、参考视频转写改编、直接粘贴正文。提供人设、卖点、知识分享、故事式口播模板，目标时长与朗读语言进入写稿提示。
- 视频学习使用独立素材，先识别并校正原文，再根据本次真实资料改写；既有视频导入继续后期仍是另一个入口。修改资料和参考视频保留当前正文与成片，重新写稿成功才使下游失效。
- 常用主播和音色可命名保存、应用和删除，使用本浏览器 localforage 存储；主播绑定形象、声音设置、动作及字幕样式。音色预设保留人物，应用后需重新制作配音与视频。
- 独立音色试听复用现有配音服务，平台通道提交前报价确认；结果、输入与任务恢复分开保存，不覆盖正式音频或成片。其他配置通道以相应服务费用为准。
- 照片说话改用独立人物动作要求，业务资料不再混入人物动作提示。新增字段纳入输入快照与本地持久化。
