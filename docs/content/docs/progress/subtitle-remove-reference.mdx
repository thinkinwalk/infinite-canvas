# 硬字幕去除优化方案

## 范围与结论

本轮通过比特指纹浏览器本地 CDP `63037`，使用独立临时标签检查了：

- 本地：`http://127.0.0.1:3000/video/subtitle-remove`
- 对标：`https://6688ai.quantv.com/video-subtitle-removal`

检查覆盖 1920×953、1440×900、1366×768、390×844 四个尺寸，并核对了 `web/src/pages/video-tool/index.tsx`、`use-video-workbench.ts`、`video-worker/app.py` 和 `video-worker.ts`。本轮已落地 P0 可达性改动和字幕任务快照；没有上传真实视频、没有创建处理任务、没有扣费。

结论：对标页把“上传 → 自动/手动标记 → 生成 → 结果/作品”压缩成一个清晰的任务入口，并在提交前展示真实积分单价；本站已经有手动框选、OCR 兜底、原音轨合成、任务记录和取消/恢复的底层能力，但仍以通用视频工作台呈现，处理服务不可用时的阻断原因不够靠近主按钮，无法让用户确认 OCR、修复引擎和输出规格是否可用。

本轮实现了：自动标记 / 手动标记入口、OCR 与字幕修复能力状态、提交前服务能力校验、手动区域列表与删除、移动端底部生成条、原片/结果并排预览，以及历史记录中的字幕输入快照。动态字幕跟踪、OCR 结果编辑和真实报价仍属于后续阶段。

## 实页证据

### 本站

- 首屏标题为“硬字幕去除”，说明是“框选字幕位置或用 OCR 检测文字”，原视频上传和作品预览并排展示。
- 字幕区只有“开启框选”开关、清空区域、一个“去除硬字幕”按钮；未框选时提示需要服务端配置 OCR，引擎能力不在生成前明确展示。
- 页面首屏显示“视频处理服务未连接”。本机 `http://127.0.0.1:8767/health` 连接被拒绝；同源网关健康请求返回 500，因此本轮没有进入真实处理流程。
- 代码中 `subtitle-remove` 要求 FFmpeg 和已配置的 Lama 修复引擎；未框选时还要求 PaddleOCR。字幕区域是归一化坐标，固定应用到每一帧，没有时间轴区间或运动跟踪。
- `repair_frames` 逐帧抽取 PNG，按框选区域或 OCR 多边形生成遮罩，交给 Lama 修复，再按原 FPS 合成 MP4，并用 `-map 1:a?` 保留原音轨。页面已经明确提示移动画面可能闪烁。
- 1920×953、1440×900 文档高度等于视口；1366×768 只有内部面板滚动；390×844 的业务区域是嵌套滚动，作品预览落在首屏下方。没有发现横向溢出，但手机用户需要继续向下滚动才能看到完整结果区。

### 对标页

- 首屏显示“视频字幕去除”和“上传视频，智能识别并去除画面中的字幕”。上传区明确支持 MP4、MOV 等格式，并同时提供选择文件和资产库入口。
- “字幕标记方式”分成“自动标记”和“手动标记”两张卡：自动模式说明无需框选、上传后直接生成；手动模式说明放大视频后框选区域。
- 上传前就显示“本次消耗 0.04 积分”；价格说明弹窗显示普通用户 `0.04 积分/秒`、会员 `0.02 积分/秒`、OPC 用户 `0.01 积分/秒`。这些是对标站实页数据，只能作为交互参考，不能直接写入本站价格。
- 桌面页左侧参数配置、右侧作品示例/我的作品/教学示例分栏；1366×768 的参数区有独立滚动容器。390×844 仍是一列长内容，顶部导航文字较拥挤，但自动/手动入口和价格按钮仍可见。

证据文件位于 `artifacts/subtitle-remove-review/`：四尺寸截图、`local.json`、`reference.json`、`price_probe.py` 和 `inspect.cjs`。截图和 DOM 采样来自临时标签，不包含凭据或浏览器存储内容。

## 主要问题与优先级

| 优先级 | 问题 | 目标 |
| --- | --- | --- |
| P0 | 本站把上传、区域选择、服务配置和结果放在通用工作台；服务未连接时主按钮仍可见，用户要点击后才知道缺什么 | 以“上传素材 → 选择标记方式 → 校验能力 → 生成”为单一主流程，能力缺失原因就近显示并禁用不可执行动作 |
| P0 | 未框选时 OCR 依赖 PaddleOCR，框选后依赖 Lama；页面没有把两条依赖、适用场景和失败边界说清楚 | 自动/手动模式卡显示真实可用性、引擎状态和限制；没有 OCR 时自动模式不可提交，没有修复引擎时两种模式都不可提交 |
| P0 | 固定区域贯穿整段视频，移动字幕可能闪烁；没有时间范围、关键帧或轨迹校正 | 第一阶段至少提供逐帧预览和区域确认；后续增加按时间段的区域、关键帧和跟踪能力，能力不足时准确提示固定遮罩限制 |
| P0 | 手机是嵌套滚动，结果和下载动作不在首屏；桌面没有专用结果对照区 | 工作台业务区独立滚动，底部生成/取消操作在业务栏内可达；手机将原片、处理预览、下载和保存动作改为连续单列或可展开区 |
| P1 | 对标页提交前显示单价和计费单位，本站只有通用模型设置，没有字幕任务的规格/费用摘要 | 生成前展示本次输入、标记方式、视频时长、处理路由、预计费用或“本地服务不计站内点数”，确认后再创建任务 |
| P1 | `VideoRecord` 没有字幕专用输入快照；历史恢复难以看出区域、自动/手动模式和 OCR 状态 | 保存原视频引用、区域列表、标记方式、OCR/修复引擎能力快照、输出规格、报价上下文和任务编号；恢复只查询原任务 |
| P1 | 结果区只有单个作品预览，无法判断字幕是否残留、边缘是否闪烁、音轨是否保留 | 提供原片/处理结果对照、时间轴抽帧检查、字幕区域放大、音频保留状态和失败原因；下载、保存素材、加入画布沿用现有动作 |
| P1 | 固定区域和 OCR 多边形都没有人工修订入口 | OCR 结果以可编辑区域列表呈现，允许删除误检、合并相邻区域、补画区域后再提交 |
| P2 | 缺少教学示例、真实本站前后对照和格式/编码说明 | 使用本站同一输入的真实样片展示可达到的效果，并说明复杂背景、半透明字幕、快速移动字幕和遮挡区域的限制 |
| P2 | 没有低成本预览或质量档位 | 在确认后评估短片预览、质量/速度选项；只有后端真实支持时才增加，不在本阶段静默改变时长、重试、并发或文件边界 |

## 推荐的信息架构

沿用 Ant Design token、中文文案、Zustand/localforage、现有 worker 上传和任务查询接口。字幕页建议拆成四个明确阶段：

1. **上传原视频**：显示格式、时长、尺寸和当前素材来源；支持本地上传与“我的素材”。
2. **标记字幕**：自动标记（OCR）或手动标记（放大视频框选）。自动模式先展示 OCR 识别框，用户可以修订；手动模式支持多个区域和清空/撤销。
3. **生成前确认**：显示标记区域数量、是否使用 OCR、修复引擎、输出编码、是否保留原音轨、预计耗时和真实计费来源。缺少能力时给出配置服务入口和可执行替代路径。
4. **结果检查**：原片/结果切换或左右对照，提供抽帧检查、下载、保存素材、加入画布、重试和恢复查询；失败信息保留任务编号和处理阶段。

桌面使用“左侧参数 + 右侧结果”的两栏布局，但参数栏和结果栏各自可滚动，生成操作固定在参数栏底部。手机改为单列连续滚动，底部保留不遮挡输入框的 sticky 操作条；作品示例、价格说明和历史记录使用抽屉或折叠面板。

## 处理能力与真实边界

- 当前字幕页同时支持两条路由：平台云模型复用后台已有 Replicate 网关和 Wan VideoEdit 配置；自部署路由继续使用 FFmpeg、PaddleOCR 与 LaMa。云路由不连接客户电脑的 `127.0.0.1:8767`，但当前只开放手动框选，并受 Wan VideoEdit 2–10 秒输入边界约束。
- 云路由会把归一化字幕区域写入编辑提示词，并请求 `audio_setting=origin` 保留原音轨；这属于模型能力请求，必须用同一业务视频验证真实去字幕效果和音轨，不能把请求参数当作效果保证。
- 自部署自动模式依赖 PaddleOCR 识别字幕多边形，手动模式可以绕过 OCR，但两种模式都依赖 LaMa 修复引擎；Replicate 云路由使用平台视频编辑模型，不依赖客户本地 LaMa。
- 当前后端对每一帧独立修复，没有字幕运动跟踪、光流稳定或时间段区域；快速移动、镜头切换、字幕渐隐和复杂纹理可能出现闪烁、残影或背景误修复。
- 当前合成会保留可用的原音轨并输出 H.264/AAC、`yuv420p`、`+faststart` MP4；页面应把这是当前 worker 的实际输出写成能力说明，编码变化需以后端验证为准。
- OCR 识别结果必须允许人工确认。没有 OCR 或修复引擎时应阻断提交并解释原因，不要把“按钮可点击”当作能力可用。
- 对标站的积分价格、示例视频和预计速度只作为交互参考；本站报价必须来自本站实际计费/路由，不能复制对标值或把对标结果当本站效果。

## 建议的实施顺序

### 第一阶段：P0 可达性和真实能力提示

1. 为 `subtitle-remove` 建立专用工作台或专用布局，前置上传、自动/手动模式卡、能力状态和生成前校验。
2. 将服务未连接、OCR 未部署、Lama 未部署分别映射到明确提示和禁用条件；保留“配置服务”入口。
3. 增加业务区滚动、移动端 sticky 操作条和原片/结果对照空态，确保四种尺寸的主按钮和结果动作可达。
4. 在不改变现有任务边界的前提下，补充固定区域的逐帧预览说明，避免暗示已经支持动态跟踪。

### 第二阶段：P1 标记、报价和任务快照

1. 增加 OCR 区域修订、多个区域管理、关键帧确认；数据结构仍使用归一化坐标，时间区间和跟踪字段在后端确认后再加入。
2. 增加字幕任务输入快照和版本保护，修改视频、标记方式或区域后使旧结果失效，恢复只查询原任务。
3. 生成前读取真实报价/本地处理费用，显示计费单位和提交摘要；确认取消不创建任务，重复点击只保留一个可恢复任务。
4. 结果区增加原片/结果对照、抽帧检查和音轨/编码摘要。

### 第三阶段：P2 质量体验

1. 用本站同一输入制作自动、手动和移动字幕的真实对照样片，标注残影、闪烁和复杂背景限制。
2. 根据已验证的 worker 能力增加质量/速度选择、低成本预览和教学示例。
3. 评估跨浏览器任务归档；不把现有 localforage 记录描述为云同步，也不在没有确认的情况下新增超时、重试、并发或文件限制。

## 验收清单

- 1920×953、1440×900、1366×768、390×844：上传、标记方式、能力提示、生成/取消、结果对照和下载均可达，无横向溢出。
- 无 worker、无 OCR、无 Lama 三种状态分别显示真实原因；手动框选可在 OCR 缺失时工作，缺少修复引擎时两种模式都不能提交。
- 自动模式显示 OCR 识别框并允许人工修订；手动模式的多个区域能保存、清空和恢复，区域始终位于画面内。
- 生成前显示本次输入和真实计费来源；取消不创建收费任务，重复点击不会创建重复处理任务。
- 处理结果保留原音轨（源视频有音轨时），输出编码与页面说明一致；原片/结果对照能检查残留、闪烁和边缘。
- 历史记录包含视频、标记方式、区域、能力快照、规格和任务状态；恢复只查询原任务，查看历史不覆盖当前草稿。
- 真实效果验收必须使用同一视频分别测试固定字幕、移动字幕、复杂背景和多语字幕；交互验收不能替代模型质量、扣费或退款验收。
