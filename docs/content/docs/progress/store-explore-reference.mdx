# 探店视频优化方案

## 范围与结论

通过比特浏览器本地调试端口 `63037` 对比 `https://6688ai.quantv.com/store-visit-video` 与 `http://127.0.0.1:3000/video/store-explore`，先完成实页对比与方案，再按用户授权实施双栏工作台与流程优化。浏览器验证使用独立标签和模拟接口，没有创建真实收费任务。

## 实施状态

专用页面已接入：独立滚动、固定操作、素材预览与稳定引用、真实资料、AI 新稿明确采用、模型能力与显式首帧、统一脚本/报价/提交规格、本浏览器作品与原任务恢复。实现位于 `web/src/pages/video-tool/store-explore-workspace.tsx` 与同目录 `store-explore-request.ts`，复用 `useVideoWorkbench` 和现有视频请求接口。

不同尺寸的实页检查与模拟流程检查已完成，记录见 [Pending Tests](/docs/progress/pending-test)。真实模型效果、真实扣费退款、独立配音字幕和多镜头合成仍需后续验收或扩展；以下保留原对比依据与设计要求。

建议为本站探店页新增专用工作台，沿用内容替换页已使用的双栏、独立滚动与固定操作区。第一优先级是按钮可达性、素材用途与规格一致性；第二优先级是素材引用、脚本编辑、报价与历史恢复。多镜头剪辑、配音、字幕属于独立能力扩展，不能用界面改造承诺已经支持。

## 实页观察

### 对标页值得采用的交互

- 左侧为输入栏，右侧是「作品示例 / 我的作品 / 教学示例」；左侧可独立滚动，底部模型、视频规格和生成按钮常驻。
- 「探店素材」支持拖放和资产库选择，文案区分门店环境、商品和服务过程；「模特选择」独立且说明人物参考用途。
- 「门店信息」可编辑、放大，AI 分析按钮靠近对应输入；「补充说明」支持 `@` 引用，生成后的脚本有独立区域。
- 模型列表、比例/时长/清晰度、预计费用与生成入口集中在底部；空输入下生成按钮禁用。
- 本次看到的默认规格为 `16:9 / 4秒 / 720p`，显示预计 `3.20积分`；素材分析标示 `0.1积分/张`、脚本 `0.1积分`。这些仅是对标站页面显示值，不能作为本站定价。
- 对标站显示门店素材最多 6 张、模特最多 3 张、单张不超过 10MB，以及补充说明 5000 字计数。本站不直接复制这些边界，沿用已确认的渠道能力与现有文件规则。
- 对标站有两个门店人物视频示例。本轮仅观察示例播放器和界面，未验证其上传素材、实际生成结果或扣费链路；「教学示例」切换后看到「教学」标签，不能据此断言教程可播放。

### 本站当前问题与证据

| 优先级 | 当前问题 | 实页 / 代码证据 | 优化目标 |
| --- | --- | --- | --- |
| P0 | 脚本与生成按钮被裁切且无法滚动到达 | 1440×900、1366×768 中按钮顶部约 `y=1451`；390×844 中约 `y=1519`；滚轮后位置不变，祖先为 `overflow-hidden` | 输入可滚动，底部动作常驻 |
| P0 | 技术配置先于业务素材，占据首屏 | 首屏先显示处理方式、云模型状态与云参数；脚本区不可见 | 门店素材与创作资料前置，模型参数收进底部与高级设置 |
| P0 | 云模式上传多图，但实际视频只用一张 | `execute("video")` 选择显式首帧，或第一张 `reference` 图片，发送 `{image}` 给 Wan | 明确「分析素材」和「本次生成输入」；提供可见首帧选择 |
| P0 | 脚本目标时长与生成规格不一致 | 写脚本读取 `config.videoSeconds`，云视频读取 `replicateFrames`，页面提供约 5 / 7.5 秒 | 同一规格驱动脚本、报价和正式提交 |
| P1 | 门店事实、视觉分析与创作要求分散且重复 | `instructions` 一个文本框混合门店名、地址、价格、风格等，另有 `analysis` | 明确事实来源与创作要求，避免视觉模型编造地址、价格、活动 |
| P1 | 模特图的使用容易被误解 | 模特图参与视觉分析；Wan 正式视频请求不直接传模特图 | 按当前模型标注「视频参考 / 分析辅助」，缺少合成首帧时不承诺人物进入视频 |
| P1 | 缺少生成前的可见费用预估与条件提示 | 当前只有生成按钮，进入 hook 后报价确认；匿名空输入时分析/生成按钮仍可点 | 前置缺失条件、实际规格、可用性与费用入口 |
| P1 | 修改输入会清空手工脚本、历史缺少输入快照 | `edit(...,"materials")` 清空 `analysis/script`；通用记录没有探店输入快照 | 保留手改内容并标记待更新；历史与当前草稿隔离 |
| P2 | 右侧首屏空态占用空间但缺少指导 | 只有模型选择和小型空预览卡 | 用当前作品、浏览器历史、使用说明形成明确结果区 |

滚动根因是 `web/src/layouts/user-layout.tsx` 固定视口高度且内容容器禁止溢出，通用 `VideoWorkbench` 的 `main` 却使用普通纵向内容布局。优先在探店专用页处理高度与滚动，不修改公共布局来影响画布等页面。

## 建议布局

保留本站顶栏与主题，标题压缩为一行「视频制作 / 探店视频」，桌面主体使用约 400–440px 输入栏与弹性结果栏；具体宽度以实际内容与窄屏验收为准。

左侧内容顺序：

1. **探店素材**：拖放、本地选择、我的素材入口；上传后展示缩略图、编号、名称与预览/移除动作。说明可上传门头、环境、商品与服务过程。数量显示当前数量，只有确有渠道上限时才展示分母。
2. **门店事实与视觉分析**：用户填写店名、地址、商品、价格、活动等真实资料；分析结果单独编辑、可放大。AI 只根据可见素材补充环境与镜头描述，未知事实保留为空或标为待确认。非餐饮门店不强制填写菜品或价格。
3. **出镜人物（可选）**：独立说明用途。支持多图参考的模型标记为人物参考；单首帧模型标明「分析辅助，不直接输入视频模型」。
4. **创作要求**：受众、风格、动作、口播需求等；支持引用素材编号。用户可不运行分析，直接填写真实资料与脚本。
5. **视频脚本**：可编辑、放大、复制；AI 写脚本使用当前素材、事实与实际生成规格。更新时保留旧稿，成功后供用户替换，失败不覆盖旧稿。

左侧底部操作区：当前视频模型、实际比例/时长/清晰度、模型能力简述、查看本次费用、主生成按钮。未登录、缺少脚本/首帧、模型停用、无效引用、素材正在保存、已有可恢复任务时给出具体原因和对应入口。仅 AI 分析/写脚本缺少文案模型配置时提示配置，不能把视频模型状态错误地当作所有阶段的阻断条件。

右侧使用「当前作品 / 本浏览器作品 / 使用说明」。当前作品显示处理进度、可恢复状态、错误和视频；完成后提供下载、保存素材、加入画布。历史查看不覆盖当前草稿；按任务显示模型、规格、时间与状态，并可显式恢复输入。

手机改为单栏内容滚动，操作区位于可见底部；保留足够底部留白，不能遮挡脚本最后一行。键盘弹出、Agent 面板展开和输入框放大需要单独验收。

## 素材与模型：必须按真实能力呈现

| 当前通道 | 界面表达 | 实际素材策略 | 规格策略 |
| --- | --- | --- | --- |
| 已启用且确认多图能力的 Seedance 通道 | 多图参考，适合门店与人物外观参考 | 复用现有能力校验，把所选门店/人物素材按稳定编号发送；不承诺所有参考都会逐一成为镜头 | 读取后台已确认的比例、时长、清晰度与原生音频能力 |
| Wan 2.2 | 经济型图生视频 | 当前探店实现使用单首帧；显式选择首帧，其他图仅用于分析和写脚本。现有普通视频页虽支持尾帧，本轮探店方案不默认扩展尾帧 | 沿用约 5 / 7.5 秒、480p / 720p；比例跟随首帧，不展示未传入的自由比例 |
| Hailuo 2.3（如后台启用且在探店接入） | 文生 / 单首帧图生视频 | 无图可文生，有图只传一张首帧；门店真实还原建议选首帧。多图仅用于分析 | 沿用 768p 的 6 / 10 秒与 1080p 的 6 秒联动 |

推荐让模型选择复用普通 `/video` 页的启用列表与能力说明，多图探店优先选择已经确认可用的参考通道；不复制对标站模型名称，不新增模型或调整后台定价。若保持现有 Wan 云路由，必须保留显式「生成首帧」而不是悄悄用数组第一张。

若用户期望人物出现在不存在该人物的门店照片中，单首帧路线需要先生成/上传人物与门店合成图；这涉及图像模型、独立费用与真实效果验收，应作为后续扩展。UI 提示不能替代这项能力。

脚本若描述多个镜头，单次短视频只能作为一个生成片段；不得把 Wan 5 秒片段描述为完整探店成片。第一阶段让脚本适配所选片段长度。多镜头分段生成、人工挑选、转场合成与完整作品归档留作后续，不在首次 UI 改造中自动串联收费调用。

## 脚本、引用与费用

- 素材编号以稳定 `id` 关联，参考已有 `materialMentionError` / `remapMaterialMentions`。移除素材后标记失效引用，不把原引用悄悄指向另一张图。
- 分析与脚本结果保留来源：素材、事实与创作要求变化时标记「输入已变化，请确认或更新」，保留用户手工内容。结果展示与当前草稿使用独立状态，不能把旧成片标成新输入的输出。
- 初始支持文本脚本直接编辑，不为了界面美观先引入复杂分镜 JSON 解析。模型提示按现有单片段能力生成镜头、动作、时间与必要的口播建议。
- 原生音频开关只在能力确认后显示；口播文字写进脚本不等于视频会有配音。字幕、TTS、音乐与剪辑服务需要单独步骤及费用，第一阶段清楚说明当前输出范围。
- 平台云模式复用 `quoteReplicate`；现有自定义/转发模型复用 `quoteVideoModel`。报价和正式提交共用同一个请求构造与规格快照；正式生成重新报价确认。
- 费用显示本站真实接口结果。文案模型走用户配置时说明按该渠道计费，不能复制对标的每张/每次固定积分；不把视频报价写成整套流程总价。
- 输入、模型、规格与登录状态变化使报价失效；旧异步报价不得覆盖新状态。同一会话可复用已经上传且仍有效的素材引用，但失效引用应走现有错误处理，不新增保留时长或重试边界。
- 创建收费任务前取消确认不生成假失败作品；提交后停止等待、取消上游、恢复查询保持不同含义。恢复仅查询已有任务，不再次提交收费预测。

## 实施顺序与文件范围

### 第一阶段：可用性与输入一致性

1. 新增 `web/src/pages/video-tool/store-explore-workspace.tsx`，路由入口只为 `store-explore` 分派到专用页；保留其他工具。
2. 实现双栏、左侧滚动、固定操作区与手机布局，复用现有 theme token、登录入口、素材选择器及上传持久化。
3. 重排素材、事实、分析、人物、要求与脚本；显式首帧选择、提交条件和模型用途提示。
4. 在 `use-video-workbench.ts` 为探店统一请求构造与时长来源，避免分析、脚本、费用和正式视频使用不同规格。
5. AI 分析不无条件检查 worker，普通图文分析直接使用已有文案模型；高级设置仅保留确有用途的配置。

### 第二阶段：创作体验与可恢复性

1. 复用普通视频页模型能力、设置与报价；支持已启用通道的多图参考并验证角色和引用一致。
2. 增加引用、脚本放大与输入变化提示；异步更新不覆盖手工脚本或新输入。
3. 为 `VideoRecord` 保存探店任务输入/模型/规格快照，浏览器历史展示当前任务输入与结果；恢复查询使用原提交配置。
4. 完成当前作品、浏览器历史、保存素材/画布与使用说明；没有本站实测样例时使用指导空态。

优先复用 `useVideoWorkbench("store-explore")`、Zustand/localforage、`ModelPicker`、`VideoSettingsPanel`、`video-capabilities.ts`、`useReplicateConfirmation` 和现有视频请求/报价接口。不要复制普通视频页整套实现，也不为单页面引入新状态管理方案。源码改动控制在探店专用页、入口、所需 hook/type/store 与必要请求适配范围内。

### 后续能力扩展

- 多镜头分段生成与合成、独立配音/字幕/配乐、人物门店合成首帧。
- 无人打开页面的归档、跨浏览器作品等独立项目；当前草稿和作品仍主要保存在本浏览器。
- 官方作品示例必须用同一本站工具、同一真实输入生成并核对文案；不得拿对标示例当本站能力证据。

## 验收清单

- **布局**：1920×953、1440×900、1366×768、390×844 无横向溢出，滚动可到达全部输入，生成按钮可见；浅色/深色、键盘、触摸、Agent 展开及放大编辑正常。
- **素材**：拖放/本地/素材库一致；错误保留旧图，缩略图无重叠；移除和调整顺序不混淆引用。切换模型清楚展示本次真正发送的素材。
- **文案**：价格、地址、促销只来自用户确认资料；脚本时间与实际规格一致；不运行 AI 也能手写脚本；输入变化和生成失败保留手稿。
- **模型**：按后台启用与能力生成；多图参考请求带正确素材，Wan 只用选定首帧，Hailuo 合法规格联动。已打开标签页刷新模型后可更新列表/可用性，保留素材与脚本。
- **费用**：真实请求与报价字段一致；旧报价失效和迟到返回处理正常；取消确认不创建收费任务，后端停用/HTTPS 阻断保持有效。文案费用与视频费用明确区分。
- **任务**：重复点击不制造重复收费任务；刷新后恢复原任务、输入与配置；停止等待与取消任务语义明确；历史查看不污染当前草稿；下载/保存素材/加入画布真实可用。
- **效果**：用一家真实门店的环境、商品、人物素材验收门头文字、空间、商品与人物一致性、动作与声音。只把模拟检查用于流程判断，真实模型效果与扣费退款另行验收。
