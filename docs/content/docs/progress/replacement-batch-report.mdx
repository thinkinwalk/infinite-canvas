# 长视频人物替换实现与评估记录

## 当前结论

已实现整片任务编排和字幕处理接口，当前进一步改为自动分段、首段预览确认后继续，已随 v0.19.63 同步部署主应用与 Worker，真实换人质量及浏览器交互仍待验收。长视频按镜头组合与时长上限拆分、逐段生成、裁去重叠再拼接。分段能降低跨镜头跟踪难度，但不能证明 Replicate 的空人物掩膜问题已解决。

后台任务只保存素材引用、规格、提示词、渠道编号、计费确认、模型任务编号和结果，不保存上游密钥。网页关闭后可继续；网站重启后需明确恢复，不自动重试收费生成。每个视频内部串行执行；不同视频之间尚无全局调度或资源隔离。任务及文件目前写本机持久化磁盘，未实现对象存储或自动清理规则。

## 自动分段与先预览流程

- 用户不再选择单片/整片；单段输入上限取 15 秒与模型支持上限的较小值，短片可容纳时不因内部切镜额外拆段。模型实际生成档位仍按其支持值选择，重叠、补齐及较长输出档位纳入真实报价。
- 先分析整片预算，再单独确认首段生成；首段通过时间轴校验、恢复原音轨后停在预览待确认状态。用户确认当前预览及剩余费用后，复用首段生成其余段并合并。刷新恢复不能绕过确认，首段重做后必须确认新预览。
- 整人替换沿用可用推荐候选排序，模型切换收进高级设置；长换脸使用专用 head-swap 接口及其独立计价，不调用 Wan30。短换脸沿用原直接生成路线。原样片存在约 0.18 秒时长差，长换脸仍需真实验收，不放宽时间轴校验。
- 本轮验证：Go 专项 14 项、前端任务/预算 5 项、Worker 分段 10 项通过。使用模拟收费任务验证首段暂停、确认与复用；未调用真实收费模型。前端开发资源返回 200，浏览器交互不可用；这些是开发期本地记录；目前 v0.19.63 已部署生产，普通用户处理服务网关、任务列表、线上静态资源和数据库完整性验证通过。下方验证及服务器适配为此前记录；CPU 字幕预清理现已下线，Wan30 使用云端联合去字幕，其他模型须先用独立云端工具处理字幕。

## 服务器适配

只读核查的生产配置为 4 vCPU、约 7.8 GiB 内存、8 GiB swap、无 GPU，并运行其他业务。现有 worker 有 FFmpeg、FFprobe 与 Whisper small，没有 PaddleOCR/PaddlePaddle、LaMa 权重或远程 GPU 地址。建议 CPU 服务负责切分、拼接、音轨和任务管理；OCR 与画面修复交给独立处理服务。`GPU_WORKER_URL` / `GPU_WORKER_TOKEN` 接口已接好，推理服务仍需平台部署，不能要求用户预先自行去字幕。

## 同素材评估方法

使用同一人物参考图和同一业务原片，先覆盖开头露脸、侧脸/遮挡、硬字幕、切镜和短镜头，再评估 3 分钟完整流程。逐段记录模型与渠道、输入秒数、扣费/退款、耗时、失败原因；检查第一帧、身份稳定、口型、背景文字、字幕漏清和接缝。以实际总花费除以验收通过的成片分钟数比较成本，而非只看每秒或每次标价。

无人镜头跳过、人物身份跟踪、自动接缝优选、时序一致的修复引擎尚未实现。0.5 秒重叠目前用于提供相邻上下文并按时间轴裁回，不代表已经消除视觉跳变。LaMa 逐帧修复仍可能闪烁；OCR/语音匹配对无音轨字幕、错字及同词招牌仍有局限。

## 已完成验证

- Go 专项：5 项新增测试，加既有计费确认和 Replicate 生命周期测试，共 7 项通过。
- Python：4 项时间轴测试、2 项真实 FFmpeg 回归通过。29.97 fps 片段对齐所选档位，避免 10.01 秒按 11 秒计费；0.12 秒短镜头补齐后拼接仍保留 0.12 秒。
- 180 秒合成视频：两次切镜、21 个 10 秒片段、共 210 秒模型输入；拼接结果 180 秒，首尾和切镜附近 8 处像素抽样一致。此测试使用未换人的片段，不是人物生成质量验证。
- 实际 worker 后处理曾验证完整原音轨、中文字幕烧录及同编号请求复用。原音轨合成使用 AAC 编码，不承诺音频文件字节不变。
- 前端新接口 3 项通过；既有 Replicate 测试另有 6 项失败，分别涉及运行环境缺少 Image 和旧路由断言。页面交互检查被自动执行策略拦截，未完成浏览器验收。
