# 视频高清优化方案

`/video/upscale` 已按 P0/P1 调整为专用工作台：左侧完成上传、输出规格与费用确认，右侧查看原片、成片和本浏览器作品。窄屏滚动、提交条件、后台报价与历史恢复已落地，保留本站导航、主题与实际模型能力；真实增强质量与 P2 同源效果对照仍待验收。

## 核查范围与实施状态

- 已经通过本地 CDP 端口连接比特浏览器，工作台标题确认是 `496-etsy企业店-工作台`，目标页面为 `http://127.0.0.1:3000/video/upscale` 与 `https://6688ai.quantv.com/video-high-definition`。调试端口会随浏览器重启变化。
- 原标签页只读取内容与截图；交互检查使用同窗口独立标签页，结束后只关闭本轮创建的页面。
- 两页初始视口为 1920×919；本地另检查 1440×900、1024×768、390×844，并用滚轮核对实际滚动。
- 本地未登录、没有原视频、没有任务记录；对标显示 0.00 积分，作品示例、我的作品与教学示例均为空。不能从当前登录提示推断本站后台未配置模型，也不能从对标空页判断处理质量。
- 方案之后已完成 P0/P1 业务实现，新增高清专用页面与输入快照工具，复用现有报价、费用确认、任务与素材存储。未上传真实业务视频或提交真实付费任务；成片质量、实际费用和退款未验收。
- 实施检查覆盖 1920×919、1440×900、1024×768、390×844、320×740，未发现横向溢出，桌面输入及手机页面能实际滚动。独立浏览器模拟流程的 10 项检查通过，包括报价竞态/取消、4K/48 fps、账号隔离、历史/刷新恢复、原任务恢复、worker 能力与 null fps、转码、停止等待后恢复；不能用模拟输出替代真实增强质量验收。报告见仓库旁 `artifacts/upscale-review/implemented-live.json` 与 `implemented-workflow.json`。
- 原始截图、页面参数与交互记录在仓库旁 `artifacts/upscale-review/`；交互草案中的状态仅用于展示布局。

## P0：恢复可靠的输入和操作

### 滚动与提交前置条件

390×844 下滚轮向下 1200px 后，内容容器 `scrollTop` 仍是 0。当前主按钮尚可见，但其后的结果区域底部被裁切；桌面空输入时尚未超高，不能推断上传视频、展开高级区之后仍能访问所有内容。

在高清专用页面建立 `h-full/min-h-0` 布局，桌面允许输入与结果区域滚动，窄屏使用单列正常滚动。提交区在桌面左栏底部常驻，移动端跟随输入内容或采用预留空间的底部操作区，避免遮挡预览。不要直接修改公共布局影响画布。

主操作应体现当前条件：

| 状态 | 按钮与反馈 |
| --- | --- |
| 未登录，使用平台云服务 | 显示“登录后使用”，点击进入现有登录流程，不进入生成流程；允许先本地选片 |
| 已登录，未选片 | “查看费用并开始”禁用，附近显示“请先上传视频” |
| 上传或读取素材中 | 显示读取状态；元信息失败时标明未知，不显示猜测值 |
| 服务未配置或不可用 | 显示准确原因与重试检查入口；管理员配置入口按权限显示 |
| 条件就绪 | 可查看费用；最终确认前不创建收费任务 |
| 已提交，正在等待 | 禁止重复提交，保留停止等待、取消任务与恢复查询的既有区别 |

### 参数必须匹配渠道能力

平台 Topaz 当前接口只接受 `720p / 1080p / 4k`，不添加对标的 2K。30/60 fps 作为常用选项，不删除当前支持的 24、25、48 等自定义整数帧率。费用说明随实际请求更新：当前后台将不高于 30 fps 的请求按 30 fps 档计价，高于 30 fps 按 60 fps 档计价；这是计费档位，不是把输出帧率改成 30 或 60。

自部署增强仍展示现有 2/4 倍和可选目标帧率，留空保持原帧率，不能套用 Topaz 绝对分辨率或云报价。当前“已配置模型与处理服务”路线对高清也进入 worker 分支，不会调用任意视频生成模型；在高清页面应把渠道简化为实际的“平台高清 / 自部署增强”，并只显示该渠道需要的设置。能力与可用状态分别读取，不把 GPU 增强缺失解释成所有剪辑功能不可用。

## P1：建立素材、费用与结果的完整工作台

### 左侧输入

按“原视频 → 输出分辨率 → 目标帧率 → 参数摘要 → 高级设置 → 提交”排列。上传槽支持点击、拖拽和从我的素材选择，沿用现有单视频替换逻辑。已上传时展示原片与真实元信息，长文件名可查看完整名称；尺寸读取失败显示“未识别”，不要把媒体服务的兜底 1280×720 当成真实原片尺寸。当前元数据没有原始 fps 字段，不在首版假装已识别源帧率。

文案建议为“提升视频清晰度与画面质量”；Topaz 名称可作为参数摘要或费用确认信息，Replicate、自部署地址、令牌与技术说明放到高级区。平台渠道无需用户填写个人 Replicate Key。云路径隐藏没有作用的通用“模型设置”按钮。

格式引导按实际接入能力与验收结果展示。现有 `video/*` 只是浏览器筛选，并不保证每种容器或编码都能预览、上传和增强。首次优化不新增经验性的文件大小、视频时长、任务超时、重试或并发限制。

### 费用

复用 `quoteReplicate` 和 `useReplicateConfirmation`，补充高清报价入口。可提供“查看费用”，有可信报价时显示总算力点、原片时长、实际分辨率与帧率，以及按后台档位取整的计算过程。素材或参数变化使旧报价失效；加载中和报价失败必须有明确状态，不能继续显示旧金额。

当前报价前需要 `uploadReplicateReference` 获得服务器可访问素材地址。应复用同一输入的上传引用，避免调整参数时反复上传整段视频；已有内容替换的引用缓存可以按实际使用扩展到高清，并保持登录账号隔离。选择本地素材和查看结果不触发云处理；费用确认取消不创建收费任务。素材时长以服务器 FFprobe 和报价为准，使用备用时长时沿用现有明确提示。

不得使用对标的 0.50 积分或代码默认价伪装成当前账户报价。服务连接、余额与上游可达性需要在登录后的实际链路验收。

### 右侧结果与记录

- “当前作品”：上传后先能查看原片；完成后切换原片/成片，显示真实输出尺寸、时长与可验证的输出规格，保留下载、保存素材、加入新画布。
- “本浏览器作品”：复用已有高清记录，展示名称、状态、参数与完成结果；失败显示原因与明确重试入口，已提交任务优先恢复查询。
- “使用说明”：短步骤与分辨率/帧率说明。没有本站真实、同输入的验证样例时不复制对标素材，不用其他工具或不同视频冒充增强效果。
- HEVC 等编码无法预览时给出准确提示，保留原输出下载；只有当前处理服务的转码能力可用时才显示“转为可播放版本”，不得声称转换一定能成功。

补充高清任务输入快照，记录当次原视频引用、处理渠道、分辨率/放大倍数与帧率。历史恢复用记录中的参数，不借用当前表单设置。当前修改参数会立即清空 `final`；建议保留上一结果并标明“对应上次设置”，等新任务成功后更新当前结果，避免用户改参数后失去下载入口。该规则需专用于高清，避免改变其他工具的失效逻辑。

## P2：真实效果对照与扩展

验收同一输入的增强样片后，再做原片/成片同步播放、同一时刻帧截图与局部放大对照。同步播放需要处理帧率、时长与音轨差异，不能用两段独立播放假装逐帧对齐。先验收人脸、文字、商品细节、运动边缘、闪烁和音轨，再上线官方示例。

批量增强、跨浏览器作品、无人在线归档和新增渠道作为独立需求，不纳入首版界面优化。现有草稿、媒体与阶段记录主要存储于本浏览器，不能标注成已支持云作品同步。

## 验收条件

1. 桌面 1920、1440、1024 宽和手机 390、320 宽，滚轮、触摸及键盘能访问全部参数、预览与操作；浅色/深色均可读，无横向溢出。
2. 未登录、无素材、服务不可用、读取失败、余额不足均有明确下一步，重复点击不会创建重复收费任务。
3. 720p/1080p/4K、30/60 fps 和自定义 24/48 fps 的请求值正确；默认仍为 1080p/30 fps；自部署仍是倍数和可选 fps。
4. 换片、改规格、切渠道后旧报价立即失效；报价与最终确认一致，取消确认不扣点，不重复上传相同素材。
5. 保留既有付费任务的状态核对和不确定状态处理；停止等待不冒充取消成功，恢复查询不重建任务。
6. 历史输入能恢复；改参数后上一结果仍可下载并标明所用旧规格；刷新后的本地媒体和任务能恢复。
7. 实际完成一段验证视频，核对输出尺寸、帧率、时长、音轨、费用、退款和 HEVC 预览/转换路径；不得用模拟接口结果替代真实模型效果验收。
